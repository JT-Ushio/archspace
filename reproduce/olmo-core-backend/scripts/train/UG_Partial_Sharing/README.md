# UG 部分共享：固定 rank512 参数预算

研究问题：UG 完全共享带来的表示限制，能否通过少量独立空间改善？

公式（按行向量约定）：

    G = (X A_s) B_sg + (X A_g) B_pg
    U = (X A_s) B_su + (X A_u) B_pu
    H = SiLU(G) * U
    Y = RMSNorm(H A_d) B_d

共享 rank 为 r_s；Gate、Up 各自独立 rank 为 r_p。每层 UG 参数：

    P_UG = r_s*(2048+2*8192) + 2*r_p*(2048+8192).

Q/K/V/O 全部独立 rank512，中间激活 Identity；原始 QK norm、RoPE
保留。Down rank512、无可学习 gain 的 RMSNorm。原始 SwiGLU SiLU 保留。
此次只改变 UG 共享比例，O/Down rank 不参与补偿，因此不能直接将 C8
当作完全匹配对照（C8 的 O496、Down520、UG568）。

| 编号 | 共享 rank | 每个独立 rank | 独立部分占 UG 参数 | 每层投影参数差值 |
|---|---:|---:|---:|---:|
| P0 | 0 | 512 | 100% | 0 |
| P1 | 560 | 0 | 0% | -163,840 |
| P2 | 480 | 80 | 15.625% | 0 |
| P3 | 320 | 224 | 43.750% | 0 |
| P4 | 160 | 368 | 71.875% | 0 |

参考每层投影参数24,117,248，全模型797,050,880。P0/P2/P3/P4精确匹配。
P1将理想共享 rank568.889向下取16的倍数560；全模型少2,621,440参数
（约0.329%），必须披露，不能称严格同参数。内部点选择遵循精确预算和
16维整除约束，故不是最初建议的12.5%/25%。

所有新矩阵沿用已有初始化：输入因子std0.02，输出因子
std=1/sqrt(r_s+r_p)，保持每个UG输出的总初始化方差。共享基础只计算一次。

在线性因子不带bias且共享输入投影复用的前提下，上面的UG参数式也等于
每token的矩阵乘加次数。因此P0/P2/P3/P4不仅投影参数相同，理论矩阵
乘加预算也相同。两个输出的总latent宽度分别为512/560/544/528；
共享的输入投影节省参数，允许每个分支拥有更宽的输出子空间。
这不是实测加速结论：分支相加、激活/归一化、通信和kernel效率另计，
最终应使用实际训练吞吐、峰值显存和完成同token预算的时间比较。

30B tokens，seq8192，global batch256，rank microbatch32768；
Muon LR0.005、WSD warmup2000/末20%衰减、FP8；1788步checkpoint并保留。
init_seed12536，data_seed34521；实际设备数和配置在运行记录中保存。
默认延续已有LM验证（每500步）和下游评估（12500步）。

主要比较最后1000步平均Train CE；同时保存全程平均、最终原始CE、验证集
CE和下游评估。短期观察沿用30B日程，不改max_duration制造短日程优势。
异常CE保留原始记录，另做明确披露的共同步数敏感性分析。单种子结果用于
筛选，胜出配置随后补种子；未确认收益前不声称新方法优于现有最强配置。

任务低优PRIORITY=1；arch有卡优先16/32卡，pool允许并行1x8；
每30分钟检查一次。每个配置有独立run/checkpoint路径，禁止重复输出写入。

## Q/K SiLU 与部分共享的交互对照

新增P0qk/P2qk，仅在对应P0/P2上把Q/K中间激活改为SiLU：
Q=SiLU(XA_q)B_q，K=SiLU(XA_k)B_k。Q/K/V/O仍独立rank512，
原始QK norm/RoPE保留；UG中间Identity、原始SwiGLU保留、Down RMSNorm512。
两组均严格797,050,880参数，训练配置与对应参照相同。

| UG结构 | Q/K Identity | Q/K SiLU |
|---|---|---|
| 独立512 | P0 | P0qk |
| 共享480 + 各自独立80 | P2 | P2qk |

完成后用同一步数/完整预算的Train CE，分别计算两个结构中的QK变化，
并报告交互项(L_P2qk-L_P2)-(L_P0qk-L_P0)。该设计不以早期CE挑选
赢家；单种子仍需重复验证。C6同时使用UG568/O496/Down520，不能代替
这里仅改变QK激活的精确对照。P2qk优先arch16/32，P0qk用pool8；
arch若排队则转pool8，输出路径独立。
