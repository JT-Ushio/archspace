# Convert a native SiTU-Up checkpoint to Hugging Face

`run_SiTU_up.sh` uses the standard OLMo3 projection matrices but changes the Up
branch of every SwiGLU block:

\[
g=W_gx,\qquad u=W_ux,\qquad
h=\operatorname{SiLU}(g)\odot 25\tanh(u/25),\qquad y=W_dh.
\]

The control introduces no parameters, so the checkpoint can use the standard
OLMo3 Hugging Face weight names. It still needs the custom files generated by
this converter; loading the result as a plain `Olmo3ForCausalLM` would silently
drop SiTU and produce different logits.

## Convert

Use the same Python environment as training. The existing `TMPDIR`, `HF_HOME`,
and other environment variables are inherited; the script does not contain or
persist any access tokens.

```bash
cd "${MOSE_JT}"

CHECKPOINT="${CKPT_DIR}/olmo3-1b-SiTU-up-5e-3/stage1/step75080"
HF_OUTPUT="${CKPT_DIR}/huggingface/olmo3-1b-situ-up-step75080"

bash run_convert_SiTU_up_checkpoint_to_HF.sh \
  "${CHECKPOINT}" \
  "${HF_OUTPUT}"
```

After conversion, the script loads the custom HF model and greedily generates
32 new tokens for three default English/Chinese prompts. Results are printed and
saved to `${HF_OUTPUT}/decode_samples.json`.

Custom prompts and decode settings can be supplied as follows:

```bash
bash run_convert_SiTU_up_checkpoint_to_HF.sh \
  "${CHECKPOINT}" \
  "${HF_OUTPUT}" \
  --decode-device cuda \
  --decode-max-new-tokens 64 \
  --prompt "Once upon a time" \
  --prompt "上海是一座"
```

The output directory must be new or empty. Conversion defaults to CPU and saves
BF16 weights. For a machine with limited memory, the final full-model load check
and decode can be skipped while retaining the lightweight config check:

```bash
bash run_convert_SiTU_up_checkpoint_to_HF.sh \
  "${CHECKPOINT}" \
  "${HF_OUTPUT}" \
  --skip-model-load-check
```

Optional converter arguments include `--tokenizer PATH_OR_REPO`,
`--max-sequence-length N`, `--dtype {bfloat16,float16,float32}`, and
`--device DEVICE`. Use `--skip-decode` to retain the full model-load check but
skip generation.

For an end-to-end numerical comparison of native OLMo Core logits and the HF
model, add `--validate-logits`. This runs an extra 60-token full-model forward
and can be slow on CPU. On a GPU machine, for example:

```bash
bash run_convert_SiTU_up_checkpoint_to_HF.sh \
  "${CHECKPOINT}" \
  "${HF_OUTPUT}" \
  --validate-logits \
  --validation-device cuda
```

FP8 in `run_SiTU_up.sh` is a training-compute setting. The persistent master
weights in the OLMo Core checkpoint are exported as BF16 by default; this does
not create an HF FP8-quantized checkpoint.

## Load and use

The converted directory contains `model.safetensors`, tokenizer files,
`configuration_situ_olmo3.py`, and `modeling_situ_olmo3.py`.

```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

model_dir = "/path/to/huggingface/olmo3-1b-situ-up-step75080"

tokenizer = AutoTokenizer.from_pretrained(model_dir, trust_remote_code=True)
model = AutoModelForCausalLM.from_pretrained(
    model_dir,
    trust_remote_code=True,
    dtype=torch.bfloat16,
    device_map="auto",
).eval()

assert type(model.model.layers[0].mlp).__name__ == "SiTUOlmo3MLP"
```

`trust_remote_code=True` is required locally and after uploading the complete
directory to a Hugging Face repository. The conversion script itself does not
upload anything.
